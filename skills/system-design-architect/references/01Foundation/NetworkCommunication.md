# Data Encoding
It is a translation between in-memory representation of data and self-contained sequence of bytes that can be sent over network.
- Language-specific formats: Java(java.io.Serializable), Python(pickle)
	- Incompatible for other languages
	- No versioning
- JSON, XML
	- Standardized encoding
	- XML is verbose, JSON does not have floating point precision
- Protocol Buffers
	- binary encoding
	- Requires a schema
	- Uses tag instead of field names in encoded data and thus, provides backward and forward compatibility.
- Avro
	- Uses writer's and reader's schema
	- Records can contain version number of schema version that it is encoded with.

# Data Evolution
## Database Schema
- Relational: One schema is active at a time. All data conforms to one schema. The schema can change using DDL.
- NoSQL: It is schema-less database so different versions of data formats can be written in the same database.

## Network Communication Schema
New and old versions of data formats might coexist at the same time.
- Rolling upgrade of a service
- Some clients have not installed the update of the app.
**Compatibility**
- Backward compatibility: Ensures that newer code can read data written by older code
- Forward compatibility: Ensures that older code can read data written by newer code

# Network Communication

## Data Transmission
There are four layers of protocols and each layer builds upon the layer that is beneath it.

### Application Layer
- HTTP and REST: Clients(and servers) can connect to servers to make requests to server's API.
	- Clients can be web browsers, native apps.
	- Predefined schemas for inputs and outputs of APIs.
	- REST emphasizes simple data formats, using URLs for identifying resources and using HTTP features for cache control, authentication, and content type negotiation
	- Service developers often use an IDL to define and document their service’s API endpoints and data models, and to evolve them over time. Other developers can then use the service definition to determine how to query the service.
- Remote Procedure Call(or RMI)
	- Request to remote service looks like calling a local function
	- Define the explicit server interface and call them across the network just like a method call in sequential code.
	- Provides location transparency with registry
	- RPC interface can be defined in IDLs. The `Stub` and `Skeleton` are objects generated by the compiler from the RMI interface definition, and these facilitate the actual remote communications. The skeleton is in fact a TCP network endpoint (_host, port_) that listens for calls to the associated server.![RPC](../assets/rpc.png)
	- gRPC (Protocol Buffers) and Avro RPC
	- Marshalling and unmarshalling can become inefficient for complex object parameters. Cross-language marshalling—client in one language, server in another—can cause problems

- Asynchronous messaging
	- Clients send their messages to intermediary messaging service.
	- Client(producer) fires and forget, confident that the message service would make the message reach the destination(consumer).
	- A message broker runs as a server, with producers and consumers connecting to it as clients.
	- Consumer provides callback to broker which it invokes when a message is available.
	- Brokers remove the message from queue when the acknowledgement from consumer is received.
	- **Asynchronous**:
		- Producers don't have to wait. Messages are buffered in queue in case consumer is not available or the producer is sending messages at speed far greater than what consumer can handle.
		- The delivery to consumers will happen at an undetermined future point in time.
	- Primitives of messaging systems
	    - Message Queue
	    - Producer
	    - Consumer
	    - Message broker: manages queues
	- **Durability**:
		- Some message brokers only keep messages in memory, while others (depending on configuration) write them to disk so that they are not lost in case of a broker crash.
		- Some message brokers automatically delete a message when it has been successfully delivered to its consumers. If you add a new consumer to a messaging system, it typically starts receiving messages sent only after the time it was registered.
		- On reboot, the broker can restore to the state before crash.
	- **Fault tolerance**:
		- Producer send the message to a named queue on broker. Producer will wait for the acknowledgement from the broker.
		- To ensure that the message is not lost, message brokers use _acknowledgments_: a client must explicitly tell the broker when it has finished processing a message so that the broker can remove it from the queue
		- If the acknowledgement is not received, broker redelivers the message. The combination of load balancing with redelivery inevitably leads to messages being reordered. 
		- Broker is single point of failure. Queues can be replicated across multiple brokers.
		- Messages published to leader are replicated to followers. Removal also follow the same.
		- With leader-follower message replication, the follower is known as a hot standby, basically a replica of the leader that is available if the leader fails. They do not support load balancing.
	- **Consumption patterns**:
		- Load balancing: Each message is delivered to _one_ of the consumers, so the consumers can share the work of processing the messages in the topic.
		- Competing consumers: Running multiple consumer threads and/or processes that concurrently processes messages.
		- Fan-out: Each message is delivered to _all_ the consumers.
		- Publish-subscribe:  When a consumer group subscribes to a topic, each message in the topic is sent to one of the consumers in the group (balancing load across the consumers in the group). If two separate consumer groups subscribe to the same topic, each message is sent to one consumer in each group (providing fan-out across consumer groups).
	- Exactly-once processing
		- Two sources for duplicate message processing
			- producer retrying a message due to acknowledgement not received: Message brokers support duplicate detection using client-generated, unique _idempotency key_ values for each message.
			- consumer fails to send acknowledgement to broker cause broker to resend: Maintaining a cache of idempotency keys.
	- Poison messages
		- The solution to poison message handling is to limit the number of times a message can be redelivered. When the redelivery limit is reached, the message is automatically moved to a queue where problematic requests are collected. This queue is traditionally and rather macabrely known as the _dead-letter queue_


### Transport Layer
It consists of protocols that ensures best-effort delivery of data.
Protocols:
- TCP: connection-oriented protocol. Before any messages are exchanged between applications, TCP uses a three-step handshake to establish a two-way connection between the client and server applications.
	- To achieve reliable packet delivery, TCP uses a cumulative acknowledgment mechanism.
- UDP: connectionless protocol, which exposes the user’s program to any unreliability of the underlying network.

A socket is one endpoint of a two-way network connection between a client and a server. Sockets are identified by a combination of the node’s IP address and an abstraction known as a _port_.

### Network Layer
Data is transmitted from source to destination using IP protocol. It consists of addressing and routing protocols.
IP defines how addresses are assigned to the nodes(IPv4 and IPv6)

- Routers: They are the devices that help in transmitting the data from source to destination. They receive the data from one network connect and place it on other network based on its destination
- DNS: resolves domain name to IP addresses. Described [here](../02BuildingBlocks/DNS.md).

Armed with a destination IP address, a host can start sending data across the network as a series of IP data packets.  
It does not attempt to compensate for the various error conditions

### Physical Layer
It manages the transmission of data in a single network segment, from node A to node B.
Network often comprises of heterogeneous machines, with different types of communication channels.
- Wired
  - LAN: Connect devices at small scale
  - WAN: traverses globe and make up the internet, using high speed fiber optics data pipelines 
- Wireless
  - Wireless Ethernet networks that use 802.11 protocol for transmission.
  - Cellular uses radio waves to transmit data between phone and cell towers that are connected through wire to the internet.
